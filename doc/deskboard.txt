SETUP                                                  *deskboard-setup*
Requires Neovim 0.11+ and snacks.nvim. Lua API:
>
  require("deskboard").setup({ demo = true })
  require("deskboard").sections(dashboard) -- Snacks section factory
  require("deskboard").open()
  require("deskboard").dispose()
<
Configure the section factory in Snacks dashboard opts, with Deskboard as a
Snacks dependency. Do not call Snacks.setup() from Deskboard setup.
Default providers and notes writes are disabled. See README.md for full options.

Opt in to trusted per-repository routing with:
>
  require("deskboard").setup({ repo_config = { enabled = true } })
<
Repository .deskboard.json files support exactly two combinations: GitHub issues
and PR reviews, or Jira tickets and GitLab MR reviews. See README.md for JSON
examples. Discovery follows the current working directory up to the nearest Git
root, including subdirectories. Neovim prompts to trust the file before providers
are enabled. Missing/rejected/invalid files disable remote providers and hide
tickets/issues and reviews panels. The dashboard opens Notes; Tab/S-Tab cycles
only Notes and Reminders. Missing configs do not produce warnings. Changing
working directory cancels old requests and switches providers/caches/panels.

COMMANDS                                             *deskboard-commands*
:Deskboard                   Open the dashboard
:DeskboardRefresh            Refresh active panel
:DeskboardReloadConfig       Reload trusted repository .deskboard.json
:checkhealth deskboard        Dependency/configuration checks (no API calls)
:DeskboardNotesNew            New structured note (requires writes opt-in)
:DeskboardNotesStatus         Change local note status
:DeskboardNotesReviewed       Mark locally reviewed, with confirmation
:DeskboardNotesVisibility     Set private/team visibility
:DeskboardNotesSearch         Literal local full-text search
:DeskboardNotesIndex          Retry safe index updates
:DeskboardNotesDelete         Confirm recoverable local trash move
:DeskboardNotesAssignID       Confirm new NOTE ID; retain previous_id
:DeskboardNotesBrowser        Local Markdown browser preview

Dashboard keys: Tab/S-Tab panels; [p/]p pages; ! status; R refresh.
Reviews: a author filter, A clear. Notes: C category, S status, t tag, Q queue,
A clear, F search, K/P details. Writable actions: + new, M status, v reviewed,
V visibility, D delete; all require notes.allow_writes=true. B browser is optional.

SAFETY                                                 *deskboard-safety*
Nothing is published to Confluence. Remote providers require explicit enablement.
No credential helper or private note root is chosen by default. Workflow edits
stay in the buffer until :w; deletion uses local trash and confirmation. Existing
note IDs and old high-water reservations must be preserved during migration.
Git checkout, pipeline and Jira-edit actions require separate explicit opt-ins.
Demo mode must remain offline/read-only. See README.md for details and limitations.

Reviews persist the last successful list in stdpath('state')/deskboard/reviews.json.
Set providers.gitlab.cache_file to override the path. Cached reviews are restored
for the same host/project on restart, then refreshed on visiting the panel (or R).
Failed requests keep the saved snapshot; successful empty queues clear it.
Only review metadata is saved, never credentials.

Repo-config mode stores separate issue/review caches and Jira snapshots below
stdpath('state')/deskboard/repositories/, isolated by checkout/provider/project.
GitHub uses gh authentication; Jira and GitLab use their existing CLI credentials.
No credentials, commands, executable Lua or write permissions belong in repo JSON.
GitHub issues and PR previews are read-only and never invoke Jira or glab.
